Get from zero to a working login in one sitting. When you are done you will have:

- OutlabsAuth installed against Postgres
- Schema migrated and an admin user
- Auth routes mounted on FastAPI
- A successful login that returns JWT tokens

::tip{to="/getting-started/introduction"}
New here? Skim [Introduction](/getting-started/introduction) first (two minutes).
::

## Prerequisites

- Python **3.12+**
- A PostgreSQL database you can reach
- Redis is optional for local demos — see [Configuration](/build/configuration)

::steps{level="3"}

### Install

```bash [Terminal]
pip install outlabs-auth==0.1.0a37
# or: uv add outlabs-auth==0.1.0a37
pip install "uvicorn[standard]"
```

You will need at least:

| Variable | Meaning |
|----------|---------|
| `DATABASE_URL` | `postgresql+asyncpg://…` |
| `SECRET_KEY` | JWT signing secret, **≥ 32 characters** for HS256 |

Generate a secret:

```bash [Terminal]
export SECRET_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(48))')"
```

### Pick a preset

| Need | Preset |
|------|--------|
| Flat roles, no org tree | `SimpleRBAC` |
| Departments / teams / hierarchy | `EnterpriseRBAC` |

Details: [Choosing a Preset](/getting-started/choosing-a-preset).

### Create the schema

Run this in a **single-process** release or prestart step — not inside every
app worker:

```bash [Terminal]
export DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5432/app
# optional: export OUTLABS_AUTH_SCHEMA=outlabs_auth

outlabs-auth migrate
outlabs-auth seed-system
outlabs-auth bootstrap-admin --email admin@example.com
# Enter a password at the hidden prompt; use the same password for smoke login.
```

Or the one-shot orchestrator:

```bash [Terminal]
outlabs-auth bootstrap --admin-email admin@example.com
```

::warning
Keep `auto_migrate=False` when you run multiple uvicorn workers. More:
[Configuration](/build/configuration) and [Deployment](/getting-started/deployment).
::

### Wire FastAPI

Save this as `main.py`. It follows the library's tested README pattern, with
migrations and background maintenance owned outside the API process.

```python [main.py]{8-9,20-21}
import os
from contextlib import asynccontextmanager

from fastapi import FastAPI
from outlabs_auth import SimpleRBAC
from outlabs_auth.routers import get_auth_router

auth = SimpleRBAC(
    database_url=os.environ["DATABASE_URL"],
    secret_key=os.environ["SECRET_KEY"],
    auto_migrate=False,  # schema was migrated in the previous step
    background_job_mode="disabled",
)
auth.prime_fastapi_routing()


@asynccontextmanager
async def lifespan(app: FastAPI):
    await auth.initialize()
    yield
    await auth.shutdown()


app = FastAPI(lifespan=lifespan)
auth.instrument_fastapi(app)
app.include_router(get_auth_router(auth, prefix="/auth"))
```

::note
Call **`prime_fastapi_routing()`** before mounting routers at import time (or
mount inside `lifespan` after `initialize()`). Call **`instrument_fastapi(app)`**
so commits finish before the response is sent.
::

For an admin console you will also mount users, roles, permissions, and so on.
Catalog: [Routers & Prefixes](/build/routers-and-prefixes).

Examples use `/v1/auth`, `/v1/users`, …. Production often uses `/iam`. Pick one
prefix family and keep it consistent for OutlabsAuth UI’s `authApiPrefix`.

### Start the API and smoke login

In the shell where `DATABASE_URL` and `SECRET_KEY` are exported:

```bash [Terminal]
uvicorn main:app --reload --port 8000
```

Open `http://localhost:8000/docs` and try `POST /auth/login` with the admin
email and the password you entered above. Or, in a second terminal, replace
`YOUR_ADMIN_PASSWORD` below with that password:

```bash [Terminal]
curl -s -X POST http://localhost:8000/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@example.com","password":"YOUR_ADMIN_PASSWORD"}'
```

You should get an access token and a refresh token. Call protected routes with:

```http
Authorization: Bearer <access_token>
```

### Protect your own routes

```python [routes.py]
from fastapi import Depends

@app.get("/me")
async def me(ctx: dict = Depends(auth.deps.require_auth())):
    return {"user_id": ctx["user_id"], "source": ctx["source"]}


@app.delete("/items/{item_id}")
async def delete_item(
    item_id: str,
    _=Depends(auth.deps.require_permission("item:delete")),
):
    ...
```

Treat the returned context as auth-owned. Use the dependency methods to make
authorization decisions instead of reading raw scope metadata yourself. See
[Authorization Dependencies](/build/authorization-dependencies) for entity,
tree, source, superuser, and advanced two-phase checks.

::

## Optional: OutlabsAuth UI

OutlabsAuth UI is a **sidecar operator console** (a separate Nuxt 4 + Nuxt UI
repo that builds to a static site). Point it at any FastAPI host that mounts
this library — full users/roles/entities/keys/audit surface when those routers
are mounted, and a solid reference if you build your own admin UI.

```bash [Terminal]
git clone https://github.com/outlabsio/OutlabsAuthUI.git
cd OutlabsAuthUI
bun install
cp public/app-config.template.json public/app-config.json
# apiBaseUrl + authApiPrefix must match your mounts; frontendProfileKey must
# name a frontend profile your host registers (remove it if there are none)
bun run dev   # http://localhost:3000 — allow this origin in your API's CORS
```

Why it exists, what workspaces cover, and Simple vs Enterprise behaviour:
[OutlabsAuth UI](/integrations/outlabsauth-ui).

## Checklist

- [ ] Postgres reachable; migrated and seeded
- [ ] `prime_fastapi_routing()` (or mount after `initialize()`)
- [ ] `instrument_fastapi(app)`
- [ ] Auth router mounted; smoke login works
- [ ] Host routes use `auth.deps`
- [ ] (Optional) OutlabsAuth UI `app-config.json` matches your prefix and frontend profile, and the API's CORS allows the console origin
