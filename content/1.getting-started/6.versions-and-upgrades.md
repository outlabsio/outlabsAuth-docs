This handbook targets **outlabs-auth 0.1.0a37**, published on 11 October 2026.
Auth and the optional Auth UI are released separately.

| Component | Contract documented here |
| --- | --- |
| Python package | `outlabs-auth==0.1.0a37`, Python 3.12+, PostgreSQL |
| Admin console | Nuxt 4 / Nuxt UI 4 static SPA; runtime `app-config.json` |
| Console backend minimum | Auth a35; its recorded release tests require the a36 example behavior or later |
| Development work | a38 is unreleased; candidate-only tenant/grant and lifecycle hooks are not part of a37 |

```bash [Terminal]
pip install outlabs-auth==0.1.0a37
outlabs-auth --version
```

An exact prerelease pin avoids accidentally resolving an older package or an
unreviewed future release. Check [PyPI](https://pypi.org/project/outlabs-auth/)
and the [a37 source](https://github.com/outlabsio/outlabsAuth/tree/v0.1.0a37)
before selecting a different version. Source-branch documentation can describe
unpublished work; it is not proof that an API exists in an installed package.

## Upgrade an existing host

1. Record the current package, application artifact, database migration head,
   and a tested recovery point. Review the selected release's migrations.
2. Build and test the exact pinned artifact in staging. Run migrations once
   from the release process; keep `auto_migrate=False` in API replicas.
3. Exercise login, refresh, logout, password recovery, invitations, and the
   permissions used by your application through its actual mounted routes.
4. Check the console's `/auth/config` discovery, frontend profile, CORS, and
   delegated-admin behavior. Release each console deployment through its own
   [production gate](https://github.com/outlabsio/OutlabsAuthUI/blob/main/PRODUCTION.md).
5. Promote only after those checks pass and retain the previous artifact.
   A database restore or rollback also needs Auth's recovery fencing; review
   [Auth recovery](https://github.com/outlabsio/outlabsAuth/blob/v0.1.0a37/docs/AUTH_RECOVERY.md).

For a37's session-generation and replay-containment behavior, see
[Sessions & Audit](/auth/sessions-and-audit). Do not infer independent tenant
isolation from an entity hierarchy: the host still owns its data-access and
transaction boundaries.
