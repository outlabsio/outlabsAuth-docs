Ship OutlabsAuth without fighting the schema or cache topology.

## Checklist

::steps{level="3"}

### Postgres

Use `postgresql+asyncpg://…`. Prefer a **direct** URL over a transaction pooler
for auth-heavy traffic.

### Secret

`secret_key` must be **≥ 32 characters** for HS256.

### Schema

Keep auth tables in a dedicated schema (for example `outlabs_auth`) via
`database_schema=` / `OUTLABS_AUTH_SCHEMA`.

### Migrate once

`auto_migrate=False` in multi-worker runtimes. Run the CLI in prestart:

```bash [Terminal]
export DATABASE_URL=postgresql+asyncpg://...
export OUTLABS_AUTH_SCHEMA=outlabs_auth

outlabs-auth doctor
outlabs-auth migrate
outlabs-auth seed-system
outlabs-auth bootstrap-admin --email admin@example.com --password '…'
# or: outlabs-auth bootstrap --admin-email … --admin-password …
```

### Redis (or memory cache)

Use Redis for shared permission cache, counters, rate limits, and token
blacklist. Use `cache_backend="memory"` only on a **single** process.

### Mount prefix

Keep a stable prefix (`/v1`, `/iam`, …) and match OutlabsAuth UI
`authApiPrefix` — see [Routers & Prefixes](/build/routers-and-prefixes).
If you deploy OutlabsAuth UI, allow its origin in the API's CORS settings (with
credentials) and keep it on the same site as the API when OAuth is enabled —
see [OutlabsAuth UI](/integrations/outlabsauth-ui#deploy-notes).

### Observability

Instrument OutlabsAuth in the API process and expose your host `/metrics` registry —
[Observability](/reference/observability).

### Maintenance owner

Keep `background_job_mode="disabled"` in every API replica. Give periodic
cleanup and sync work one external scheduler/worker owner — see
[Background Maintenance](/getting-started/background-maintenance).

::

## Multi-worker / multi-instance

| Concern | Guidance |
|---------|----------|
| Migrations | One-shot prestart / release job — never every uvicorn worker |
| Permission cache | `redis` (+ `redis_url`) so invalidation is shared |
| Memory cache | Only for single-process hosts |
| Refresh revoke / sessions | `store_refresh_tokens=True` (default) |
| Immediate access kill | `enable_token_blacklist=True` + Redis |
| Background maintenance | Disabled in every API process; one external owner per database/environment |

::caution
Do **not** use `cache_backend="memory"` when multiple workers must see each
other's permission invalidations immediately.
::

## Security recovery

a37 adds migration `20261011_0026`: nullable user security
epochs and retained platform-protection history. Migrate through the packaged
CLI before starting the new workers. Its default lock budget is 5 seconds;
`migrate --lock-timeout` accepts 1ms–30s. Invalid or incomplete Auth indexes stop
the migration and need explicit operator repair.

Restoring a database/cache backup or returning to validators predating security
epochs requires closed admission, fresh signing secrets held outside the backup,
a fresh cache namespace and worker restart, and reconstruction of later credential
and grant revocations. Routine downgrade refuses to remove the security columns;
retaining columns does not make an older validator safe. Reopen only after stale
credentials are rejected and the approved replacement identities pass.

The detailed external admission and recovery checklist is the repository's
[Auth recovery runbook](https://github.com/outlabsio/outlabsAuth/blob/main/docs/AUTH_RECOVERY.md).
These changes remain unpublished; use the accepted release commit when preparing
a recovery, and qualify the public artifacts before changing consumer pins.

## Health

`outlabs-auth doctor` is read-only and safe on prod for preflight.

| Exit code | Meaning |
|-----------|---------|
| `0` | Healthy |
| `1` | Check / plan failure |
| `2` | Missing `DATABASE_URL` |
